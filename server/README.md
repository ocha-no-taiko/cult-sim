# 対戦サーバ

Tailscale 上の1台で動かす前提の、小さな WebSocket サーバ。
ゲーム本体（`../dist`）も同じポートから配るので、**参加者はこのサーバのURLを開くだけ**で遊べる。

## 動かす

```bash
cd ..            # kaiso/
npm run build    # ゲーム本体をビルド（対戦サーバが配る）
cd server
npm install      # 初回のみ
npm start        # 既定では :8787
```

参加者には `http://<このマシンのTailscale名>:8787/` を開いてもらう。
例：`http://mymachine.tailnet-name.ts.net:8787/`（`tailscale status` で自分のマシン名が分かる）

同じ **部屋ID** と **合言葉** を入れた人どうしが同じ対戦に入る。

### HTTPSにしたい場合

`tailscale serve` を使うと ts.net の正規証明書で HTTPS になる。

```bash
tailscale serve --bg 8787
```

この場合は `https://<Tailscale名>/` を開く。クライアントは自動で `wss://<Tailscale名>/ws` を見にいく。

### 別マシンでサーバだけ動かす場合

ゲームを GitHub Pages 側で開き、対戦サーバだけ別に指す構成もできる。
ロビー画面の「接続先を指定する」に `ws://server-machine.tailnet-name.ts.net:8787/ws` のように入力する。
ただし GitHub Pages は HTTPS なので、その場合はサーバ側も `wss://`（＝`tailscale serve`）である必要がある。

## 何をサーバが持っているか

各教団の経営シミュレーション自体は**各クライアントで走る**。サーバが持つのは、
クライアントに勝手に決められると困るものだけ。

| サーバが持つもの | 理由 |
|---|---|
| 共通の時計（開始時刻と1日の長さ） | 全員が同じ日を生きるため。止められない |
| 各教団の**闇度**（他のクライアントには決して送らない） | 秘匿情報。暗殺の判定に使う |
| 暗殺の判定 | 闇度を見せずに勝敗を決める必要がある |
| 決着の先着判定 | 誰が最初に到達したかの順序 |
| 公開情報の配信 | 信者数・資金・警戒度・表の事業など |

身内対戦を前提にしているので、**クライアントが自己申告する数値そのもの**（信者数や闇度）は信頼している。
改造クライアントによる詐称までは防いでいない。完全に防ぐにはシミュレーション自体をサーバで回す必要がある。

## 設定

| 環境変数 | 既定 | 意味 |
|---|---|---|
| `PORT` | 8787 | 待ち受けポート |
| `MAX_PLAYERS` | 8 | 1部屋の定員 |

ルールの数値は `rules.mjs` にまとめてある（暗殺の費用・必要な闇度・逆襲の条件など）。

## 動作確認

```bash
npm start                # 別のターミナルで起動しておく
node test-match.mjs      # 入室・暗殺・逆襲・先着判定をひと通り検証する
```
